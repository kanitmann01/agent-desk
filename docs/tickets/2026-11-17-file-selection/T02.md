# T2: Wizard workbook builds become configurable instances

Part of specs/006-file-selection-and-wizard-fix.md (issue #123). The wizard fabricates a
`reports/*.xlsx` permission for workbook asks, so a wizard-built "track my sales" widget
watches a folder that usually does not exist and offers the user no way to say where
their data is. The bundled tracker already proves a better shape: config-backed, no
glob, no file, configured per instance through the picker.

## Context

The deterministic compiler composes the manifest: fixed permissions with a workspace glob
mirrored into the widget's data source file, plus the ui-schema card. Validator rules
already accept the config-backed shape (workbook kind, empty filesystem read, no
data-source file, plugin data write) and forbid a config-backed plugin from also
declaring a data-source file, so the new output is validator-clean with no validator
changes. Only workbook builds change; JSON, HTTP, and calendar builds keep the
declarative glob shape.

## Scope

- A workbook-source wizard build composes the config-backed shape: workbook config kind,
  empty filesystem read, plugin-data write, widget data source of the workbook watch type
  without a file. The install lands in the setup state (no columns confirmed), and the
  dashboard renders its wireframe card with the Set up entry, exactly like the bundled
  tracker.
- The approval summary copy stops naming a fabricated glob for workbook builds: it says
  the widget reads a workbook the user picks in setup. Preview sample rows still render.
- Non-workbook builds are byte-identical in shape to today.
- The pilot flag, validator gate with capped self-repair, and escalation behaviour are
  unchanged; the composed draft must pass the shared validator before preview exactly as
  today.
- The wizard remains Class D only and no-LLM-by-default; endpoint-configured behaviour is
  untouched.

## Acceptance criteria

- [ ] A workbook wizard build installs as a config-backed plugin in setup state, and its
      dashboard card shows the wireframe with Set up rather than reading any glob.
- [ ] The composed workbook manifest has no data-source file and an empty filesystem
      read, and passes the shared validator unchanged.
- [ ] The approval summary for workbook builds names the setup handoff, not a
      fabricated path.
- [ ] A JSON-source wizard build still composes the declarative glob shape and reads its
      file as today.
- [ ] Approving a workbook build end-to-end (answer forms, approve) yields a working
      installed plugin record with a digest and pilot flag.
