# T1: The wizard's approve step finishes on an approved page

Part of specs/006-file-selection-and-wizard-fix.md (issue #123). Reproduced 2026-11-17:
a plain form post to the wizard approve action answers 200 JSON, so clicking "Add widget"
parks the browser on the raw response document at the approve URL with no completion
screen, no summary, and no next step.

## Context

The wizard's describing and answer steps already answer form posts with redirects so the
no-JS flow works; only approve returns JSON unconditionally. The wizard page renderer has
states for describing, questions, preview, escalated; approval today just shows the
preview again with the install result. The page needs a real approved state.

## Scope

- A form-encoded POST to the wizard approve action answers 303 and redirects to the
  wizard session page, which renders a new approved state: the installed plugin's id and
  version, the pilot badge, the one-line does/reads/never summary, the removal hint, and
  a primary call to action that leads to pointing the new plugin at real data (the
  instance setup entry once the later tickets land; the plugin's manage surface until
  then). Nothing is installed twice; the approve action stays idempotent-refusing when
  the session is not in preview.
- A JSON request to the same action keeps today's 200 JSON contract byte-for-byte in
  shape (status, pilot, summary, install), so scripted installs are untouched.
- JSON request detection follows the same request-shape check the answer step uses for
  form submits; no new header vocabulary.
- The error page family is untouched. Escalation and the repair cap behave as today.

## Acceptance criteria

- [ ] A form post to approve redirects (303) to the wizard session page, and the fetched
      page shows the approved state with the install summary and no raw JSON anywhere.
- [ ] An approve post from the preview state still installs exactly one plugin; a second
      approve post refuses with the existing not-in-preview semantics.
- [ ] A JSON POST to approve still returns 200 with the install document.
- [ ] A form post whose description/session is stale (unknown session id) still surfaces
      the existing unknown-session error page.
- [ ] The full no-JS walk (describe form post, answer form posts, approve form post)
      completes without any raw JSON screen.
