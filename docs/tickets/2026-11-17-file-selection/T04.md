# T4: Row selection in the setup modal: drag, brush, select all

Part of specs/006-file-selection-and-wizard-fix.md (issue #123). Today picking the rows a
plugin tracks means ticking checkboxes one at a time in the setup sheet; there is no
select-all, no drag, no range select, and the confirm payload never records which rows
were chosen, so the widget's read cannot honor a visual selection.

## Context

The setup sheet's preview grid already renders the file's headers and first rows, supports
header clicks for value/label assignment, and offers the suggestion helper. This ticket
extends that grid into the reusable selection surface the spec describes, and makes the
confirm call carry the selection. The modal contract on the desk (scrim, dialog role,
focus trap, Escape, focus restore) is the marketplace sheet's; the dashboard's setup sheet
predates it and has no focus trap.

## Scope

- The preview grid gains row selection gestures: click toggles a row, dragging across
  rows selects (or deselects, starting state respected) the whole sweep, shift-click
  fills the range between two anchors, Select all and Clear act on the previewed rows,
  and a live count of selected rows is always visible.
- Checkbox semantics stay for keyboard and pointer-free use; the gestures and the
  checkboxes stay one consistent selection state.
- The confirm call carries the ordered list of selected zero-based data rows; the stored
  tracking document records the selection, and the reader honors it (the widget and its
  skill read exactly those rows). A confirm without a selection keeps today's meaning, so
  existing instances are untouched.
- Confirming a selection against a stale preview (file changed underneath) is refused
  with the existing stale-config semantics rather than a new failure shape.
- The modal meets the desk's dialog contract: scrim click, Escape, focus trap, focus
  restore on close, busy and error slots. It is a named reusable component with a generic
  preview prop so further data kinds can reuse it; workbook is the kind wired here.

## Acceptance criteria

- [ ] Dragging across ten rows selects those ten; shift-click selects the inclusive
      range; Select all selects every previewed row; Clear empties the selection; the
      count matches at every step.
- [ ] The confirm request body carries the selected row indices, the stored config
      records them, and the plugin's read returns exactly those rows' values.
- [ ] A confirm without selection keeps today's default behaviour, and existing
      confirmed instances keep rendering.
- [ ] Escape closes the modal, focus returns to the opener, and tab is trapped inside
      while open.
- [ ] Component tests cover the gestures, the payload, and the dialog contract; the
      dev-proxy scan passes for any backend path the modal calls.
