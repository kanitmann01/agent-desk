# T5: Manage view can configure a config-backed plugin

Part of specs/006-file-selection-and-wizard-fix.md (issue #123). Configuring a plugin's
file and rows is only reachable from a dashboard card today. After installing something
from the marketplace, the manage surface shows lifecycle actions but no setup entry, so
the user has to know to hunt for a dashboard wireframe card to point the plugin at data.

## Context

The marketplace detail page's manage view already lists installed-plugin lifecycle
actions against the marketplace API envelope. The instance endpoints are the same ones
the dashboard card uses. This ticket surfaces instances in the manage view and opens the
same reusable selection modal from there; no new backend endpoints, one new surface for
existing ones.

## Scope

- The manage view of an installed config-backed plugin lists its instances (name,
  configured file or setup state) and offers Set up for a new instance and Edit for an
  existing one, both opening the shared selection modal flow.
- The manage view of a non-config-backed plugin is unchanged.
- The lifecycle actions, consent sheet, and everything else on the manage view are
  unchanged; the setup entry rides the same marketplace client envelope and error
  handling.
- A config-backed plugin with the historical alias pattern shows its resolved instance
  setup, not a second config surface.

## Acceptance criteria

- [ ] Installing a config-backed plugin and opening its manage view shows the instances
      list with a Set up action that opens the selection modal; completing the flow
      confirms an instance and the dashboard card appears.
- [ ] Editing an existing instance from the manage view opens the same modal preloaded
      with its config; a re-confirm updates the grant.
- [ ] A plugin without config kinds shows no setup entry and its manage view renders
      exactly as today.
- [ ] The marketplace client error envelope surfaces a refused action (for example the
      instance cap) as a visible error, not a silent no-op.
- [ ] Component tests cover the manage view for a config-backed plugin, a plain plugin,
      and the cap error path; the dev-proxy scan passes.
