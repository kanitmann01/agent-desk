# T1: JSON exports browse, preview, and track like workbooks

Part of specs/007-real-data-audit-and-settings.md (demo 2026-11-18). Reproduced 2026-11-17:
dropping a .json export into the instance setup flow fails at preview: preview_table has a
csv branch and an xlsx branch and nothing else, so a JSON file is handed to
parse_workbook_file and answers a confusing read error. The picker's dialog filter also
lists workbooks only.

## Context

The instance setup contract is already format-neutral above the reader: it wants
{headers: list[str], rows: list[list[str]]}, chooses columns by header name, and indexes
rows by position. JSON is the easiest format to add because the export is already a
table: an array of objects, or an object holding one list of objects under any key.

## Scope

- preview_table gains a .json branch: an array of objects becomes headers (union of keys,
  first-seen order) and rows (values stringified, missing keys empty); an object with a
  single list-of-objects value is unwrapped to that list; a list of scalars becomes one
  "value" column. Non-table JSON raises the same plain-language read error the csv path
  raises, never a traceback.
- The native pick dialog accepts .json next to .xlsx/.xlsm/.csv.
- read_tracker needs no change: it consumes preview_table's contract, so a confirmed JSON
  instance sums its chosen rows identically.
- Tests: preview shape for the array form and the wrapped form, error for non-table JSON,
  and a tracker instance over a JSON fixture returning the summed value and rowsSeen.

## Acceptance

1. POST to the plugin preview endpoint over a JSON fixture returns headers and rows.
2. An instance confirmed over that fixture returns the aggregated value of its chosen
   rows.
3. An .xlsx preview is byte-for-byte the same shape as before this change.
