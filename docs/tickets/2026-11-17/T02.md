# T2: The model reviews the user's own column and row choice

Part of specs/007-real-data-audit-and-settings.md (demo 2026-11-18). Reproduced 2026-11-17:
suggest.py asks the model which columns it would pick for a staged file, before the user
has chosen anything. The real user flow is the reverse: the user clicks Amount, clicks a
label column, selects rows, and only then would a reviewer be useful. There is no endpoint
that takes a selection and answers "this pairing makes sense / this one does not, try X".

## Context

The disclosure vocabulary already exists (DISCLOSURE_ROWS, DISCLOSURE_HEADERS) and the
request builder already caps size and strips the path. What is new is the direction of the
question: an evaluation of a selection rather than a proposal for a file. Failure must not
block the flow, because the demo may run with no endpoint configured: the answer in that
case is a skipped check with a plain cause, and confirmation proceeds.

## Scope

- suggest.py gains evaluate_choice(request, choice, complete) -> {verdict, message,
  recommendation?}. The prompt asks one JSON object: verdict "ok" or "adjust", a one-line
  message, and optional recommendation {labelColumn, valueColumn, rows, reason}. Names are
  validated against the preview headers and row indices against the row count; anything
  that fails validation is dropped, never applied.
- A deterministic heuristic reviewer runs when no endpoint is configured or the call
  fails: it flags a label column that is entirely numeric or a value column that is not
  numeric, returning verdict "unchecked" with the cause and no recommendation. Confirm is
  never blocked.
- setup_flow.evaluate(runtime, cap, instance_id, ..., complete) stages the same disclosure
  text and returns {disclosure, verdict, message, recommendation, error}.
- Endpoint POST /plugins/<id>/instances/<iid>/evaluate, JSON in, JSON out, same auth and
  gate as suggest; 200 for every model outcome including skipped.
- UI: after row selection the setup sheet's primary action becomes "Check this choice";
  the answer renders in one line (verdict + message); a recommendation renders as an
  Accept button that rewrites the sheet's label/value/rows, and a Keep mine that proceeds;
  no recommendation shows Approve. Accepting visibly changes the highlighted header and
  selected rows before Confirm.
- Tests: evaluated apply/decline paths, validation drops bad names, no-endpoint path
  returns unchecked 200, confirm after unchecked still stores tracking.

## Acceptance

1. With an endpoint: a request whose choice pairs a numeric column with a label column
   returns verdict and message; a recommendation appears when the model proposes one.
2. Accept stores the recommended tracking; decline stores the original.
3. Without an endpoint: 200, verdict "unchecked", cause in the message, Confirm works.
4. The file path never appears in the request payload (existing cap test extended).
