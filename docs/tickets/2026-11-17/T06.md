# T6: One settings card, and a browser sweep that proves the demo

Part of specs/007-real-data-audit-and-settings.md (demo 2026-11-18). Reproduced
2026-11-17: /settings is a 3,264 px stack of mismatched blocks: headings with no body,
swatch grids for three themes, one Endpoint card, a separate gate page elsewhere, and two
card dialects. The demo also needs proof in the browser, not only in pytest.

## Context

settings_view.py hand-composes sections; the dashboard uses WidgetCard/CellHead with its
own chrome. pages.py owns the page shell and rail. The demo runs on 127.0.0.1:8765 with a
real session cookie.

## Scope

- One card component for Settings: title, optional purpose line, body, actions row. Every
  section (Endpoint, Desk and sample switch, Calendar source, Mail source, Plugin
  registry, Capabilities and gates, Activity entry point, Where the app opens) renders
  through it. No section is a heading alone; no duplicate control (the endpoint test lives
  in one place); the three theme chips become one segmented control.
- Geometry: two-column card grid at >= 1200 px, one column below; cards never overlap or
  overflow horizontally at 1280 and 1600 px.
- A written walkthrough at docs/demo/2026-11-18-evp.md with the demo script (what the
  presenter clicks and says), the evidence table (step, what was clicked, what appeared,
  screenshot file), and the rail sweep result.
- Browser verification in this environment: open the live server, walk Browse -> preview ->
  rows -> evaluate -> accept/decline -> confirm -> dashboard card, and sweep every rail
  link plus /settings/activity and /peers; capture console errors, overlap scan, scroll
  widths; fix what fails inside this ticket set.

## Acceptance

1. Settings renders in the one card shape at both widths with no overlap or overflow.
2. The browser walkthrough reaches a dashboard card showing the file's real numbers.
3. Every rail destination renders content and no console error appears except favicon.
4. docs/demo/2026-11-18-evp.md records the run with screenshots and a pass/fail table.
