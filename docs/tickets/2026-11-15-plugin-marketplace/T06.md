# T6: Installed, Publisher Studio, publisher list, and /plugins redirect

Part of #97.

## Context

Install without management is a trap: a user cannot see what is installed, what changed, what is waiting for consent, or how to publish. The old server-rendered `/plugins` page is an operator form and should not remain the primary surface.

## Scope

- Routes: `/marketplace/installed`, `/marketplace/plugin/:id/manage`, `/marketplace/studio`, `/marketplace/publishers`, `/marketplace/publisher/:id`.
- Installed list: status, version, source, as-of freshness, pilot badge, update available with scope diff, pending consent with the added scopes, rollback, purge with typed confirmation, share and unshare with peers, subscribe to a peer plugin.
- Manage page: detail plus actions for that plugin, including release history and local data purge.
- Publisher Studio: start from an installed plugin, a folder path, or a template; validate; preview with the sample render; semver suggestion; required changelog; SPDX license choice and distribution grant; publish as pending review; list my releases with deprecate and yank.
- `GET /plugins` responds 303 to `/marketplace/installed`; the rail link and the dev proxy test are updated to the new route.
- Install, update, consent, rollback, purge, share, subscribe, publish, deprecate, yank, and report all go through the marketplace API from T4.

## Acceptance criteria

- [ ] `/plugins` returns a 303 to `/marketplace/installed`, and the rail no longer points at the old page.
- [ ] Installed renders one row per installed plugin with status, version, and update state.
- [ ] An update with widened scopes renders the diff and does not auto-consent; accepting posts consent and clears the pending state.
- [ ] Rollback calls the API and the row reverts to the prior version.
- [ ] Purge requires typing `delete-data:<id>` and shows the server error when the text does not match.
- [ ] Sharing toggles the peer-shared flag and the installed row shows it.
- [ ] Studio validation failure shows the rule and the field; success shows a preview and a semver suggestion; publishing posts a pending-review release and shows the pending state.
- [ ] Deprecate and yank update the release row.
- [ ] `devproxy.test.ts` and the rail expectations are updated, not deleted.
