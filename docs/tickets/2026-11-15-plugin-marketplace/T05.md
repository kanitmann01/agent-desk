# T5: Discover, Search, Detail, and Pack screens

Part of #97.

## Context

The SPA has no router and no marketplace. Deep links 404 because the server only serves `/` and `/static/spa/*`. A manager cannot browse, search, inspect permissions, or consent from the UI. This ticket builds the discovery half of the store: the surface where trust is earned.

## Scope

- Routes: `/marketplace` (Discover), `/marketplace/search`, `/marketplace/category/:category`, `/marketplace/plugin/:id`, `/marketplace/pack/:id`.
- A pure `parseRoute(path)` function plus a `pushState` history router. No router dependency. Back and forward work.
- Server fallback serves the SPA shell for `/marketplace` and `/marketplace/*` after the same session gate; the SPA renders a not-found view for an unknown route.
- Cards: category, tags, publisher, verification badge, risk tier, source label, one-line summary.
- Detail page: live sample render with a sample chip, summary and highlights, plain-English permission sentences with the setting each depends on, generated "can never" list, publisher proof, signature fingerprint and digest, dated validator report with a re-run action, version history with capability diffs, alternatives, report action.
- Search: plain-language query over name, summary, tags, category, and question text. Empty result state offers categories.
- Install consent sheet: scopes grouped as read, network, and derived, plus the "can never" list. Pack detail shows the member list and installs with one consent sheet.
- Accessibility: route change announced, focus moved to the main heading, semantic headings and lists, no color-only status.

## Acceptance criteria

- [ ] A deep link to `/marketplace/plugin/ar-aging` returns the SPA shell and renders the detail page after the API resolves.
- [ ] An unknown `/marketplace/unknown` renders the not-found view, not a blank page.
- [ ] Discover renders catalog cards from the API stub; filtering by category and searching "overdue invoices" both work.
- [ ] The detail page shows a sample chip, permission sentences, the can-never list, publisher proof, signature fingerprint, validator report date, and version history.
- [ ] Installing from the detail page opens the consent sheet, and the POST carries the plugin id and version.
- [ ] A pack installs all members with one POST and one consent sheet.
- [ ] Keyboard-only navigation reaches every action; route change is announced.
- [ ] `parseRoute` tests cover every route plus trailing slash and unknown path.

## Tests

SPA component seam: new component tests for Discover, Search, Detail, Pack, consent sheet, and router, with a fetch stub. Vitest plus testing-library, consistent with `frontend/src/test/shell.test.tsx`.
