# T9: Communication plugins (3)

Part of #97.

## Context

Mail is the most sensitive surface and the easiest place to lose trust. These plugins read metadata only (counts, senders, ages, thread state), never bodies, and the detail page must say so in one sentence.

## Scope

| id | Question | Source | Lead element |
|---|---|---|---|
| `outlook-digest` | How much mail, and from whom? | mail-digest | metric + list |
| `vip-watch` | Who important is still waiting on me? | mail-digest | list with ages |
| `waiting-on-you` | Which threads did I leave hanging? | mail-digest | list |

- `outlook-digest` keeps its id and upgrades to v2.
- All three read the existing metadata bridge only. They never open a message body, never read attachments, never send.
- `vip-watch` uses the VIP list from settings and shows the age of the oldest waiting item.
- `waiting-on-you` flags threads where the last message is inbound and older than the waiting threshold.
- Categories `communication`; the can-never list includes "read message bodies" and "send mail".

## Acceptance criteria

- [ ] All three validate as v2 and appear in the bundled catalog.
- [ ] Each executes against the metadata bridge fixture and returns the documented lead value.
- [ ] A missing bridge renders blank with the bridge setting name; a bridge older than 24h renders stale.
- [ ] No plugin declares a body-ingest or send capability, and the validator rejects one if added.
- [ ] `outlook-digest` keeps its id and installs over 0.1.0.
- [ ] The detail page surfaces the metadata-only sentence from the manifest.

## Tests

Registry package seam: fixture bridge with known counts and ages, plus blank and stale cases, plus a test asserting the manifest permissions contain no body or send scope.

## Out of scope

Real Graph or IMAP connectors, note or Teams integrations, packs (T12).
