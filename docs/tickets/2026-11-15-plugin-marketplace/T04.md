# T4: Marketplace API and policy eligibility

Part of #97.

## Context

The marketplace SPA needs a JSON contract. Today `/api/plugins` returns widget-shaped records, `/api/registry` returns a flat list, and no endpoint exposes detail, installed management, publish, or policy eligibility. This ticket defines the contract and the eligibility rules behind it.

## Scope

- Read routes: `GET /api/marketplace/catalog` (q, category, source, risk filters), `/plugin/`, `/installed`, `/publisher/`, `/policy`, `/audit`.
- Mutation routes: `POST /api/marketplace/install`, `/update`, `/consent`, `/rollback`, `/uninstall`, `/purge-data`, `/enable`, `/disable`, `/retest`, `/publish`, `/deprecate`, `/yank`, `/quarantine`, `/report`.
- Session cookie plus Origin and Host guard on every route, with the existing 401 and 403 behavior. JSON errors are `{error, message, details}` with stable codes.
- Eligibility from the signed policy: mode (open, curated, private-only), allowed publishers, allowed categories, risk ceiling, network allowlist, enabled sources, kill switch, minimum revocation epoch, signature requirement, version policy. Each plugin returns `eligible` plus a reason.
- Install refuses blocked plugins with `policy:blocked-publisher`, `policy:blocked-category`, `policy:risk-ceiling`, `policy:network-not-allowed`, `policy:kill-switch`, `policy:signature-required`, `policy:revoked`.
- Catalog merges sources with a label: `bundled`, `org`, `peer`. Peer catalogs are read-only. Offline returns the bundled plus installed catalog without error.
- Install and update responses include the consent scopes and whether the update widens scope.
- Legacy `/api/plugins` and `/api/registry` stay functional for one release and are marked deprecated in their docstrings.

## Acceptance criteria

- [ ] An unauthenticated request gets 401; a wrong Origin gets 403; a missing session on every new route is covered by a test.
- [ ] Catalog filters compose and return plugin cards with category, tags, publisher, risk, and source label.
- [ ] A kill-switched plugin is ineligible and install returns the kill-switch code.
- [ ] A network plugin is ineligible under a policy whose allowlist is empty, and eligible when the host and publisher are allowed.
- [ ] An update that widens scope returns pending consent with the added scopes; a narrowing update does not.
- [ ] Rollback to the previous version returns 200 and the installed version reverts; purge without the typed confirmation returns the existing confirmation error.
- [ ] Unknown plugin returns 404 with `catalog:not-found`.
- [ ] The legacy routes return the same data as before.
