# T1: Per-user plugin config and read grants

Part of specs/004-personal-agent-plugins.md.

## Context

Every bundled plugin bakes a path, a column, or a threshold into its manifest. The validator then requires that path to match `permissions.filesystem.read`, so a user cannot point the card at their own file without publishing a new manifest. The host has no place to store a confirmed choice. This ticket adds that place and the check that refuses any other path. No picker UI yet. No plugin manifest is edited yet.

## Scope

- A host store at `${pluginData}/instances/<instanceId>/config.json` with `schemaVersion` 1, `instanceId`, `name`, `source`, `tracking`, `confirmedAt`, and `suggested`. The host writes it. Plugin manifests do not gain a write glob for it.
- A grant record beside the config: the absolute path, the time, and the consent decision. The grant is one file, or one folder only when the user selected a folder.
- The reader, given a plugin id and an instance id, returns the confirmed config or "no config". It does not fall back to `dataSource.file`.
- A read of a workbook, csv, or markdown path is allowed only when the path is the granted path, `confirmedAt` is set, and the path is under the workspace or was accepted on the existing scope-widening consent sheet.
- A path outside the workspace without that acceptance is refused with a named reason, and nothing is parsed.
- Manifest field `config.kinds`, a list of source kinds from the spec. The validator accepts an empty `filesystem.read` when every file-reading source is config-backed and declares no `file` glob. A config-backed source that also declares `file` is `over-permission`.
- Existing manifests that still declare `file` keep validating and keep their current behavior until a later ticket moves them. This ticket must not break the 25 current plugins.
- Class D rules are unchanged: shell `"none"`, empty `permissions.network.allow`, no plugin HTML. Add a check that `permissions.llm.allow` is false on a Class D manifest.

## Acceptance criteria

- [ ] A plugin with no config reads no user file and reports no config.
- [ ] A confirmed path under the workspace is the only path the reader will return for that instance.
- [ ] A sibling of the granted file is refused.
- [ ] A path outside the workspace is refused until the consent decision is recorded, and is then allowed as that one file.
- [ ] A manifest with `config.kinds` and an empty read list validates. The same manifest with a `file` glob does not.
- [ ] A Class D manifest with `llm.allow: true` fails validation and the message names the field.
- [ ] The current 25 plugins still validate and their existing reads still resolve the declared glob.

## Tests

- New `tests/test_plugin_config.py` for the store, the grant, the refusal, and the consent acceptance.
- Extend `tests/test_validator_schema.py` (or the lint module's tests) for `config.kinds`, the empty-read allowance, the `file` pairing, and `llm.allow`.

## Out of scope

Pickers, suggestion, card rendering, and edits to the 25 manifests. Those are T2 through T11.
