# T10: Desk-state callbacks, health, and the two briefs

Part of specs/004-personal-agent-plugins.md.

## Context

`PluginWidgetRunner` is constructed without `desk_state`, so Audit digest, Compliance posture, Plugin health, and Update radar are blank on every real read. Health and Update radar share the selector `runtime`. Morning Brief and Weekly Review count how many of four hardcoded plugins returned a number, and their lists are plugin ids. Weekly Review depends on Plugin health, so it is blank whenever health is blank.

## Scope

- Pass three callbacks into the runner from the server: `audit`, `policy`, and `runtime`.
- Audit returns recent events: time, action, plugin id, outcome. The card is a watcher timeline, capped at 8, with the total in the footer. A missing callback and an empty log use the two T6 sentences.
- Policy returns the mode sentence and the checks the policy engine already has, as checklist items. No handwritten checklist in the plugin.
- Runtime returns two lists: plugins whose last read failed or is stale, and plugins whose installed version is older than the catalog. Plugin health shows both. `update-radar` redirects to Plugin health. The seven-day delta is removed.
- Morning brief and weekly review store a list of instance ids the user checks. The text is a local template over those cards' latest payloads: next event, waiting count, tracker delta, deadlines, week-load hours, health failures. A missing member omits its sentence. The card is blank only when every member is blank, and then it names the first missing connection. The text does not contain a plugin id. No model call.
- Morning uses the day sentences. Weekly uses the week sentences from the spec.

## Acceptance criteria

- [ ] With the callbacks unset, the three desk cards show the "not available" sentences and no sample number.
- [ ] With fixture callbacks, audit shows the fixture events, compliance shows the fixture checks, and health shows both lists.
- [ ] Updating `update-radar` opens Plugin health.
- [ ] A morning brief with calendar connected and mail missing mentions the next event and does not mention mail or a plugin id.
- [ ] A morning brief whose every member is blank names the first missing connection and shows no count.

- A server test that `PluginWidgetRunner` is constructed with the three callbacks.
