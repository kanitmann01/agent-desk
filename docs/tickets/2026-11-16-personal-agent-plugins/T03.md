# T3: Column, sheet, and range picker

Part of specs/004-personal-agent-plugins.md.

## Context

Staging a file is not enough. Aging needs an amount and a date. The tracker needs a label and a value. The scorecard needs a target. Today those names are manifest literals, and a workbook that uses different headers blanks the card with `missing-column`. The user has no way to point at the headers they actually have.

## Scope

- After a workbook or csv is staged, the host reads the chosen file locally and shows the sheet names, the header row, and the first 20 data rows.
- The user picks the sheet, the header row, an optional range, and the columns that plugin's job requires. Required columns are declared by the plugin as roles (`label`, `value`, `date`, `target`, `key`, `amount`), not as header strings.
- A preview of the first 20 rows highlights the chosen columns. Confirm writes the T1 config with `confirmedAt` and `suggested: false`.
- A missing required role blocks confirm and names the role. It does not write a partial config.
- Changing columns on an already confirmed file updates the config. Changing the file goes back through T2's grant rules.
- The preview is not sent to the endpoint. This ticket does not add suggestion.

## Acceptance criteria

- [ ] A workbook with headers `Customer` and `Amount` can be confirmed as an aging source by assigning those columns to `label` and `value`, and the reader then totals `Amount`.
- [ ] Confirm is refused while a required role is unset, and the config file is absent.
- [ ] Only the first 20 rows are included in the preview payload the page receives.
- [ ] A csv and a markdown heading picker (Notes: list the headings, the user picks one) both confirm through the same store.
- [ ] The old manifest column names are not consulted once a config exists.

## Tests

- A markdown fixture with two headings for the Notes role `heading`.

## Out of scope

The suggestion button (T4) and the card redraw (T5).
