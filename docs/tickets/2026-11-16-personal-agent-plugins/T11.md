# T11: Migration, packs, the catalog pin, and the authoring fixture

Part of specs/004-personal-agent-plugins.md.

## Context

T7 through T10 redirect old ids one at a time. The packs, the catalog copy, the skills, and the authoring guide still describe 25 plugins, eight-card packs, and Excel Report Watch as the reference example. The committed catalog pin is what made Discover drop every summary. This ticket finishes the migration and is the last one, because it describes the set the earlier tickets produce.

## Scope

- Rewrite `registry/packs.json` to the three packs in the spec. Competitor Watch stays out of every pack. Weekly Review is in CFO and Ops. Follow-up is in none. The manager pack no longer installs three calendar views plus a count.
- Rebuild `bundled-catalog.json` from the survivor manifests, including `icon`, `summary`, and source kind. Deprecated ids stay resolvable for this release, marked deprecated, and are absent from packs.
- Move the Class D reference fixture to `registry/examples/class-d/`. It is not an `index.json` entry and not a catalog card. `docs/design/plugin-authoring-v2.md` documents `config.kinds`, the rule that a personal plugin does not hard-code a user path, and points authors at the example directory.
- Skills: one tracker skill, and the three surviving skills (`day-briefing`, `mail-overview`, `research-recap`) updated so they do not name a glob. Deprecated plugins ship no skill.
- Samples across the survivors use generic labels and contain no personal names. Each sample is labeled by the existing Sample data chip and is producible by the host from the fixture.
- Update `docs/known-limitations.md` for the page-watch allowlist and remove the sentence that describes Competitor Watch as hard-coded to `example.com`, once that is no longer true.
- The README's marketplace paragraph lists the survivor jobs instead of the count 25.

## Acceptance criteria

- [ ] Each pack installs only survivor ids, and a deprecated id is rejected by the pack installer with a message that names the survivor.
- [ ] Discover shows the summary and a non-plugin icon for every survivor, from the committed catalog, without relying on a manifest merge at request time.
- [ ] `registry/examples/class-d/` validates as a Class D plugin and does not appear in `registry/index.json`.
- [ ] No survivor sample contains "Contoso", "Priya", "Acme", or "example.com/pricing".
- [ ] The authoring guide describes `config.kinds` and the grant rule.

## Tests

- The pack tests, pointed at the new membership.
- A catalog test that every survivor card has a non-empty summary and an icon other than the fallback only when the manifest's icon is other than `plugin`.
- The example fixture passes `validate_plugin`.

## Out of scope

New jobs. A personal exception to the network allowlist. Anything in PR #117's shell.
