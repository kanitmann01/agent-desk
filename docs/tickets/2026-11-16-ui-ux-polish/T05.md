# T5: Pressed primary buttons answer

Part of specs/003-ui-ux-polish.md.

## Context

Primary buttons and the research send control raise their shadow on hover and do not change while pressed, except a slight brighten on the send control. The commitment checkbox transitions every property, which the interface guidelines reject and which can move layout.

## What to build

Pressing a primary button or the research send control darkens it slightly, using color only, and the checkbox box animates only color, background, and border. Reduced motion still collapses every transition.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Scope

- Pressed state is a brightness filter on the primary button and the send control, matching the existing duration.
- The checkbox box lists transition properties explicitly.
- Buttons and links set touch-action manipulation so a double-tap does not zoom-delay the click.
- No change to the hover shadow, the radius, or the label.

## Acceptance criteria

- [ ] Primary and send controls darken on press and do not move.
- [ ] The checkbox box does not transition all properties.
- [ ] Reduced-motion still short-circuits transitions.

## Tests

Stylesheet contract test for the press filter, the explicit checkbox transition, and the existing reduced-motion rule.

## Out of scope

New animations, ripples, or a loading spinner inside the button.

## References

Spec 003, user stories 22-24. Design language motion rules. Web interface guidelines: no transition all.
