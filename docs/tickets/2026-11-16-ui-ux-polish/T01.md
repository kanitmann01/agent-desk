# T1: Shell states announce and recover

Part of specs/003-ui-ux-polish.md.

## Context

The dashboard shell has three centered states: still loading, session expired, and the server unreachable. They are plain headings and paragraphs. A screen reader is not told that loading is in progress or that a failure needs attention, and keyboard focus stays on the document instead of the recovery.

## What to build

Priya sees a quiet loading card that says the desk is still reading, announced as a polite status. If the session is dead or the server cannot be reached, she hears an alert, focus sits on the heading, and Try again is the next control.

**Blocked by:** None (can start immediately).

**Status:** done

## Scope

- Loading is a status region, busy, with the existing sentence ending in one ellipsis character.
- Expiry and load-failure are alert regions. Each heading can take programmatic focus and is focused when that state appears. The heading is not in the tab order. Try again stays a button.
- No new colors, no spinner animation, no change to the words except the ellipsis.

## Acceptance criteria

- [x] While the dashboard payload has not arrived, the loading sentence is announced as a polite status and marked busy.
- [x] A 401 renders an alert whose heading is focused, with Try again available.
- [x] An unreachable server renders an alert whose heading is focused, with Try again available.
- [x] The loading sentence ends with the single ellipsis character.
- [x] Governance and trust loading lines use the same ellipsis character.

## Tests

Frontend shell suite: extend the centered-state tests for the status and alert roles, the busy flag, the ellipsis, and focus on the failure heading.

## Out of scope

Marketplace route loading (those pages already use status text). Server-rendered pages.
