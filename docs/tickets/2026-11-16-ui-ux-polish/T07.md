# T7: Catalog icons have no filled chip

Part of specs/003-ui-ux-polish.md.

## Context

Discover cards, plugin detail, and pack headers draw the plugin glyph inside a green-soft rounded square. The design language allows one icon family and no icon backgrounds. Color on those chips reads as decoration, not status.

## What to build

The glyph stays, in the primary green, with no filled tile behind it, on the catalog card, the detail header, and the pack header.

**Blocked by:** None (can start immediately).

**Status:** done

## Scope

- Remove the filled background, the fixed tile size, and the tile radius from those three icon slots.
- The stroke icon and its accessible hiding stay.
- Status chips (verified, risk, sample) are unchanged. They are status, not decoration.

## Acceptance criteria

- [x] Catalog, detail, and pack icons do not paint a filled background.
- [x] The glyph is still the primary green.
- [x] Verified and risk chips still use their status colors.

## Tests

Stylesheet contract test that those three icon rules do not set a filled background.

## Out of scope

Redrawing the icon set or varying card sizes in the catalog grid.

## References

Spec 003, user stories 29-30. Design language: no icon backgrounds; color only for status and the one action.
