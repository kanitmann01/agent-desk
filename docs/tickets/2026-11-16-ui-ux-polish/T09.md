# T9: Server-rendered pages share the polish

Part of specs/003-ui-ux-polish.md.

## Context

Inbox, assistant, settings, activity, memory, mail, capabilities, and peers are server-rendered HTML with their own stylesheet. The SPA polish does not reach them. A manager who leaves the dashboard still sees the wrapping rail and the older type.

## What to build

A later pass carries the one-row narrow rail, the sentence-case labels, the pressed primary button, and the visible skip-link focus onto those pages, using the same tokens.

**Blocked by:** T3, T4, T5 (the SPA versions define the behavior to copy).

**Status:** deferred

## Scope

- Deferred. The SPA is the surface this spec implements.
- When picked up, do not fork a second visual system. Match the SPA.

## Acceptance criteria

- [ ] Each server-rendered rail page uses one scrolling row below the same breakpoint.
- [ ] Primary buttons on those pages darken on press.
- [ ] Skip targets on those pages show a visible focus ring.

## Tests

The existing server HTML tests that already pin rail markup, extended for the new rules.

## Out of scope

Redesigning those pages' content.
