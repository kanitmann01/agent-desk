# T3: Narrow navigation is one scrolling row

Part of specs/003-ui-ux-polish.md.

## Context

Below 980px the rail wraps into several rows. On a 390px window the greeting starts only after three rows of navigation, and a focused control can sit under the sticky strip. The skip link targets a main region that is not programmatically focusable.

## What to build

On a narrow window the navigation is one horizontal row. Priya scrolls it to reach every destination, the brand stays visible at the start of the row, and each item is a 44px target. Tabbing does not leave the focus ring under the strip. Skip to main content moves focus onto the main region.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Scope

- At the existing 980px breakpoint the rail no longer wraps. It scrolls on the inline axis, with scroll containment.
- The brand sticks to the inline start of that scroller and keeps the rail's own background.
- Rail links on that breakpoint have a 44px minimum block size.
- The document reserves scroll padding for the strip.
- Both main regions (dashboard and marketplace) are programmatically focusable so the skip link can land.

## Acceptance criteria

- [ ] The narrow-window rail rule sets nowrap and inline overflow instead of wrapping.
- [ ] Rail links at that breakpoint are at least 44px in the block direction.
- [ ] The page reserves scroll padding so content can clear the sticky strip.
- [ ] Dashboard and marketplace mains can receive programmatic focus.

## Tests

Stylesheet contract test for the narrow-window rail rules and scroll padding. A shell render test that the dashboard main is programmatically focusable.

## Out of scope

Changing the desktop rail, the collapse control, or server-rendered pages.

## References

Spec 003, user stories 12-17. Web interface guidelines: sticky content must not cover focus. Taste skill: targets tall enough to hit, focus not under a bar.
