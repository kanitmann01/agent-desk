# T3: Narrow navigation is one scrolling row

Part of specs/003-ui-ux-polish.md.

## Context

Below 980px the rail wraps into several rows. On a 390px window the greeting starts only after three rows of navigation, and a focused control can sit under the sticky strip. The skip link targets a main region that is not programmatically focusable.

## What to build

On a narrow window the navigation stays a wrapping strip, because both stylesheets forbid sideways scrolling so an entry cannot clip away. The words drop (each link already has its accessible name) so the strip is icon-height and the greeting starts higher. Each item is a 44px target. Tabbing does not leave the focus ring under the strip. Skip to main content moves focus onto the main region.

**Blocked by:** None (can start immediately).

**Status:** done

## Scope

- At the existing 980px breakpoint the rail still wraps and still does not scroll sideways. Labels and the brand words hide. Links are at least 44px.
- The document reserves scroll padding for the strip. The server-rendered sheet gets the same rules so the two rails stay one system.
- The dashboard main is programmatically focusable so the skip link can land. The marketplace main already is.

## Acceptance criteria

- [x] The narrow-window rail still wraps and does not scroll sideways, on both stylesheets.
- [x] Rail links at that breakpoint are at least 44px, and the words are hidden.
- [x] The page reserves scroll padding so content can clear the sticky strip.
- [x] The dashboard main can receive programmatic focus.

## Tests

Stylesheet contract test for the narrow-window rail rules and scroll padding. A shell render test that the dashboard main is programmatically focusable.

## Out of scope

Changing the desktop rail, the collapse control, or server-rendered pages.
