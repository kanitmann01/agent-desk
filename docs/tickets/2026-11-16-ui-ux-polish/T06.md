# T6: Research bar uses the search mark

Part of specs/003-ui-ux-polish.md.

## Context

The research command bar leads with a decorative sparkle. The empty research card already uses a search mark for the same job. The field is 15px, off the type scale, and has an accessible name but no name attribute for assistive autofill.

## What to build

The bar shows the same search mark as the empty research card, hidden from assistive tech. The field is body size, named `question`, and set so a password manager does not treat it as a login. Asking with Enter still works, and a failed ask still keeps the text.

**Blocked by:** None (can start immediately).

**Status:** done

## Scope

- Replace the sparkle with the shared search icon.
- Field type size is 14px.
- The field keeps its aria-label, and gains name and autocomplete off.
- Send label, Enter to ask, and Shift+Enter for a newline stay as they are.

## Acceptance criteria

- [x] The command bar does not render the sparkle path.
- [x] The field is named question, autocomplete off, and still labeled Research question.
- [x] Enter submits and a failed ask keeps the text.
- [x] The field's type size is the 14px body size.

## Tests

Extend the command-bar shell tests for the name and autocomplete attributes and the absence of the sparkle. Stylesheet contract test for the 14px field.

## Out of scope

Changing the placeholder sentence or the send button label.

## References

Spec 003, user stories 25-28. Design language: no decorative icons. Web interface guidelines: named fields, autocomplete.
