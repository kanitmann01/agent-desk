## Slop findings

1. One green did every job: button, link, up-delta, healthy dot, selected nav. Status and action were the same color.
2. Cards were a repeated soft shadow (`0 0 0 1px` plus two blurs) on a warm beige field. That is the default "paper SaaS" template.
3. Plus Jakarta Sans is on the taste skill's banned list (with Inter, Poppins, Space Grotesk).
4. The rail was ten generic stroke icons plus a green monogram tile.
5. Marketplace plugins sat in an equal card grid, each with a filled icon chip.
6. Type wandered off any scale: 10, 10.5, 11, 11.5, 12.5, 13, 13.5, 15, 16.5, 17, 19, 25, 30.
7. Uppercase tracking on eyebrows, table heads, and server field labels.
8. The research bar started as a sparkle. Even after it became a search mark, it was still a decorated well.
9. Hover lifted a shadow by two hundredths of opacity. Nothing answered a press except a brightness filter.
10. Narrow navigation hid the words and kept the icons, so the phone was a row of anonymous marks.
11. `frontend/src/marketplace/marketplace.css` used `outline: none` on the main region until a later patch; focus still depended on a green ring that matched the only accent.
12. Server pages (`src/agentdesk/server/pages.py` stylesheet) repeated the old tokens, so leaving the dashboard changed the product.

## Web interface guidelines, file:line (before the redesign)

These are the findings that were still true of the polished-but-templated UI, or that the redesign had to keep fixing:

- `frontend/src/index.css` transition list on the checkbox was `all` until T5; the redesign keeps explicit properties.
- `frontend/src/marketplace/marketplace.css` search input uses `outline: none` because the well draws the ring (`:focus-within`). Kept, with the well as the visible focus.
- `frontend/src/components/CommandBar.tsx` field now has `name` and `autocomplete="off"`.
- Loading strings that used `...` were changed to `…` in `Admin.tsx` and `Trust.tsx`.
- `src/agentdesk/server/pages.py` had `text-transform:uppercase` on labels. Removed in this redesign.
- Icon-only controls that remain (overflow, collapse) keep `aria-label`.

## Taste-skill rules skipped

The skill is written for marketing sites. These rules were not applied, and why:

1. Photographs on the hero, and 12–20 photos on a place page. This is an internal desk. There is no place and no product photograph.
2. One section per screen, hero alone on the first screen. Priya needs the figure and the decisions on the first screen. Hiding them below a hero would make the tool worse.
3. Hero entrance (`data-enter`) and a dealt scroll moment. A tool she opens every morning should not animate in.
4. Shader, WebGL, and award-site scenes. Not a campaign page.
5. Real full-color product icons (Outlook, Excel). Drawing those logos would claim integrations and recreate the icon soup.
6. Card lift of 2px and photo zoom. The reference uses a hard offset, not a float.
7. 60–80 words of marketing copy per screen. The sentences already in the product are the copy.
8. Street address and contact rules. The app has no public address.
9. Copying the skill's `assets/` kit into `public/`. The app is the existing React and Python shell, not the static starter.

The gate was armed and run with `--quick` against the local desk. The first run scored `GATE: QUICK 28`. A later run that hit the desk signed out scored `GATE: QUICK 9`, all against the session-required card. The authenticated rerun on the morning-brief dashboard scored `GATE: QUICK 24`. The blocking ids are marketing-page checks: `hero-screen`, `hero-fill`, `one-section`, `section-height`, `section-air`, `copy-headline` (it wanted the category noun in the h1), `heading-scale` (it flagged the 64px figure), `flush`, `nav`, `container`, and `container-edges`. `focus-ring` flags `h1:focus, h1:focus-visible { outline: none }` and the same rule on `.mkt-page-head h1`. That removal is intentional: headings are not controls, and focusing the marketplace title on route change was drawing a ring after load. Keyboard controls keep the square ink `:focus-visible` ring. `field-label` flags the research textarea, which has an `aria-label`. Waivers were not written to force a PASS.
