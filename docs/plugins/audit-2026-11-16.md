# Plugin audit, 2026-11-16

Audit of the 25 bundled plugins in `registry/plugins/`. No product code was changed. The dashboard redesign on PR #117 was not edited. Screenshots of the running app are attached to the pull request as `plugin-cards/*.png`. They are not committed here.

Read against commit `727809d` on `main`. The catalog the running app serves is `src/agentdesk/marketplace/bundled-catalog.json`, and that pin wins over the checkout manifest (`build_bundled_catalog` keeps the pin and skips the manifest merge).

## How this was read

For each plugin: `manifest.json`, `widget.ui.json`, `sample.json`, `README.md` when present, and `skills/*/SKILL.md` when present. Then the host that actually runs them: `src/agentdesk/plugins/sources.py`, `src/agentdesk/plugins/execute.py`, `src/agentdesk/plugins/render.py`, the calendar day view, the mail watcher, and `PluginWidgetRunner` construction in `src/agentdesk/server/app.py`. Card chrome: `frontend/src/marketplace/MarketGrid.tsx`, `frontend/src/marketplace/Sample.tsx`, `frontend/src/dashboard/PluginCardView.tsx`. Validator rules: `src/agentdesk/validator/lint.py` and `schema.py`.

The app was started with a fresh data directory (`python3 -m agentdesk.server --port 8765 --no-browser`). Captures:

- `dashboard_builtin_empty.png` — the desk before any plugin is installed. The built-in sales and calendar cards already ask the user to connect a workbook and a calendar.
- `catalog_grid.png` — Discover, all 25 tiles.
- `<plugin-id>.png` — the marketplace sample card for that plugin, which is the only card UI a plugin has until it is installed.

A fresh desk installs nothing, so the dashboard has no plugin cards to photograph. What an installed card would draw is `PluginCardView`: a metric becomes a large number, and every other element kind becomes a single note line. The manifest sizes `2x1` and `2x2` are ignored. Every installed plugin card is `span-4`.

## Why they look and act alike

Five facts, shared by the set:

1. **The catalog pin erases the manifest.** `bundled-catalog.json` stores id, name, category, tags, and risk. It does not store `icon`, `summary`, `description`, or `contributes`. Because a pin replaces the live manifest, every Discover tile gets `icon: plugin` (the same plug glyph), an empty summary, and `capabilities.sources: []`. Detail pages say "Data sources: none declared" even when the manifest on disk names `excel-watch` or `mail-digest`. Confirmed by calling `build_bundled_catalog` on `registry/` and by the Discover screenshot.
2. **One sample shell.** `SamplePreview` puts every plugin in the same `WidgetCard`: title, a "Sample data" stamp, an auto-fit grid (`minmax(180px, 1fr)`), and a footer. Element kinds differ, and the marketplace does draw lists, sparklines, and checklists. The frame does not. Week Load is the only sample with a real sparkline. Several tables draw their headers and then empty rows (see below).
3. **The dashboard renderer drops the kinds.** `PluginCardView` special-cases `metric` and renders anything else as `element.text`. A list, table, sparkline, timeline, checklist, delta, progress bar, or status line does not survive installation.
4. **Array tables render blank.** `render.py` keeps a table row that arrived as an array as an array. `Sample.tsx` reads `row.primary`, `row.secondary`, and `row.meta`. A/R Aging's bucket table, Audit digest's event table, and Source Ledger's source table show column headers and empty lines. The screenshots match the code.
5. **The job is a manifest literal.** Paths, column names, targets, windows, and sample companies are written into the plugin. There is no per-user config file. `first_permitted_match` opens the first file that matches the glob, sorted by path. Two plugins that share `${workspace}/reports/*.xlsx` read whichever workbook sorts first.

The built-in sales card already has the interaction the owner described: "Connect a workbook", and an empty state that names the missing file instead of showing zero. None of the 25 plugins do that. A missing file becomes an attention card whose cause names the glob.

Samples are labeled "Sample data", which matches the design-language rule that fabricated numbers be marked. The samples are still not what the host would compute. They are a second, invented schema.

## Top hard-coding problems

1. **Paths and columns live in the manifest.** Examples: `${workspace}/finance/ar*.xlsx` with `Customer`, `Balance`, `DueDate`; `budget*.xlsx` with `Line`, `Spent`; `kpi*.xlsx` with `Metric`, `Actual`; `revenue*.xlsx` with `Region`, `Booked`; `ledger*.xlsx` and `bank*.xlsx` with `Reference`, `Amount`; `${workspace}/reports/*.xlsx` shared by Excel Report Watch and Sales 24h Delta; `${workspace}/ops/contracts*.xlsx` with `Vendor`, `NoticeDate`; `${workspace}/commitments/*.csv` with `Owner`, `Due`; `${workspace}/notes/*.md` heading `Actions`.
2. **Targets and thresholds are literals.** Revenue progress target `1000000` USD. Budget target `250000` USD with `targetGood: down`. Aging bounds `[30, 60, 90]`. Renewal and follow-up windows `30d` and `90d` / `24h` as manifest strings. Mail follow-up is `FOLLOW_UP_DAYS = 2` and the digest is `DIGEST_HOURS = 24` on the watcher, not on the plugin. `MAIL_USER = "employee@example.com"` is the address treated as the desk's owner when deciding who has already replied.
3. **Samples invent a schema the host does not emit.** Sales "changed rows" need a key column the manifest does not declare. KPI "on track" / "off track" needs a target column the reader never opens. Source Ledger titles are hard-coded in the sample; the store persists bare strings and the host writes an empty title. Follow-up secondary text is a promise sentence; the reader only has `Owner` and `Due`. Meeting Prep's checklist is a deck and a notice date in the sample, and "Confirm with {name}" at runtime. Competitor Watch's price lines require a JSON body; the URL is an HTML page, and the reader returns a hash plus the first 200 characters.
4. **The metric and the label disagree.** Reconciliation's `value` is `len(both)`, the keys present on both sides. The card labels it "Unmatched". Renewal's window keeps dates that are not older than 30 days, which includes dates months ahead. Excel's `windowNote` is always the 24-hour snapshot sentence, including on the 30-day and 90-day plugins.
5. **Desk-state plugins cannot run.** `PluginWidgetRunner` is constructed with calendar, mail, and research only. `desk_state` stays `None`. Audit digest, Compliance posture, Plugin health, and Update radar render the blank cause "The host provides no {selector} state callback." Health and Update radar both select `runtime`, so wiring one callback would feed both cards the same blob.
6. **Command cards count plugin ids.** Morning Brief requires `sales-delta-widget`, `calendar-today`, `outlook-digest`, `research-brief` and aggregates with `count`. Weekly Review does the same with `sales-delta-widget`, `follow-up-watch`, `week-load`, `plugin-health`. A missing member blanks the whole card. The sample rows are those ids.
7. **One network plugin, pointed at example.com.** `optionalPermissions.network.allow` is `example.com`, the prompt asks about `https://example.com/pricing`, and `known-limitations.md` already records that the default policy's empty `networkAllowlist` refuses it with `policy:network-not-allowed`.
8. **The catalog the app serves is not the manifest.** Discover cannot show the summary or the icon the author wrote. Detail cannot name the data source.

Fictional names used as if they were the user's books: Northwind, Bluebird, Contoso, Tailspin, Acme, Fabrikam, Lumen, Priya Nair, Priya Raman, Marcus Bell, Marcus Lee, Dana Whitfield, Sam Okafor. They appear only in `sample.json`. The marketplace chip does say "Sample data".

## Per plugin

### A/R Aging (`ar-aging`)

**Purpose versus behavior.** The manifest says it totals cash stuck, buckets 0–30, 31–60, 61–90, and 90+, and lists the oldest balances, reading only `${workspace}/finance/ar*.xlsx`. The host sums the `Balance` column (aggregate defaults to sum) and, when `DueDate` parses, fills `bucketTable` with labels `0-30`, `31-60`, `61-90`, `90+` (no "days" suffix, amount formatted, count as a string). The oldest list is the first eight mapped rows: customer, amount, and the date, not "96 days". A missing file or a missing column is an attention state that names the glob or the column. That part is honest. The sample's five named customers and the "96 days" meta are not what a read produces.

**Hard-coded.** Glob `finance/ar*.xlsx`. Columns `Customer`, `Balance`, `DueDate`. Buckets `[30, 60, 90]`. Schedule `0 8 * * 1`. Sample companies and the total 184,500.

**Overlaps.** Budget Burn, KPI Scorecard, Revenue vs Target, and Sales 24h Delta are the same shape: open one workbook, reduce a column, list rows. Aging is the one that needs buckets, so it is a different card once the columns are chosen by the user.

**Card.** Marketplace sample is a metric, an empty bucket table, and a customer list, inside the shared shell (`ar-aging.png`). Installed, the list and the table collapse to notes.

**Verdict.** Keep. Configurable workbook, amount column, date column, and bucket edges.

### Audit digest (`audit-digest`)

**Purpose versus behavior.** The README says the host audit log supplies the event count, the rows, and the window. The source is `desk-state` / `audit`, and the permissions are empty, which is right for a host log. The runner is built without a desk-state callback, so a read returns blank: "The host provides no audit state callback." The sample (148 events, five invented rows including a plugin id `board-pack-export` that does not exist) is the only time the card has numbers.

**Hard-coded.** The table columns `When`, `Action`, `Plugin`, `Outcome`. The sample's window sentence. No user path, which is correct.

**Overlaps.** Compliance posture (policy), Plugin health and Update radar (runtime). Different questions, same unwired source family. The audit log itself is a different selector and should stay its own card.

**Card.** Metric 148 and a table whose body is empty (`audit-digest.png`), because the sample rows are arrays.

**Verdict.** Keep, once the host passes an audit callback. The card should be a timeline of real audit events, capped, with no fabricated plugin ids in the preview.

### Budget Burn (`budget-burn`)

**Purpose versus behavior.** "Are we burning faster than plan?" The host sums `Spent` by `Line` on the first `finance/budget*.xlsx` and compares with `target: 250000`, `targetGood: down`. Under the cap, status is "on track" and tone is `ok`. Over it, status is "over target". The progress element repeats the same 250,000 as a literal, unit USD. `windowNote` is the generic 24-hour snapshot line from the excel binder, not "Spent in the last 30 days". The 30-day `window` only drops rows when a date column exists, and this manifest has no `dateColumn`, so every row is summed.

**Hard-coded.** Glob, columns `Line` and `Spent`, target 250,000, unit USD, good direction down, schedule `0 7 * * *`. Sample value 187,500 and the sentence "75% of budget used".

**Overlaps.** Revenue vs Target is the same progress bar with the opposite good direction and a different file. Sales 24h Delta and Excel Report Watch are the same workbook read without a target.

**Card.** A progress bar and a status line in the shared shell (`budget-burn.png`).

**Verdict.** Merge into the Workbook tracker as a named instance: the user picks the workbook, the spent column, the cap, and whether under or over is the good direction.

### Calendar Today (`calendar-today`)

**Purpose versus behavior.** The manifest matches the host. `calendar-read` uses `day_view`: `eventsToday`, `todayRows` bound as `rows` (title, start `HH:MM`, location), and `nextEventTitle`. No model call. Empty and stale bridges return the bridge's cause and bind nothing. The skill `day-briefing` restates the same two facts. The sample's "Q4 pipeline review" is sample data. The live card does not invent events.

**Hard-coded.** No file of its own. The calendar file is the desk's, chosen on the calendar walkthrough. The plugin cannot point at a second calendar. Schedule hourly. The list title "What is left" shows today's rows, including events that already started.

**Overlaps.** Meeting Prep and Week Load read the same view. Meeting Prep repeats the next title and today's rows. Week Load repeats today's rows.

**Card.** Count, a short list, and the next title (`calendar-today.png`). Same shell. This is the agenda pattern, and it should not also be a big number.

**Verdict.** Keep. First run should point at the existing calendar walkthrough. Drop nothing else onto this card.

### Competitor Watch (`competitor-watch`)

**Purpose versus behavior.** "Did the competitor pricing page change, and what changed?" The source is `http-get` of `https://example.com/pricing` with allow `example.com`. The reader hashes the body, sets `changed` after the second fetch, and does not diff lines. A JSON object becomes rows. An HTML page becomes `value` = the first 200 characters and no `rows`. The sample's three price changes are not a possible output. Redirects are refused. Filesystem read is empty, which the validator requires for `http-get`. The default policy allowlist is empty, so the plugin is not eligible until an operator adds the host. The README says it is excluded from packs. `packs.json` excludes it from the manager pack only.

**Hard-coded.** URL, host, the consent prompt text, the daily schedule, and the sample prices ($29, $79, 15 percent).

**Overlaps.** Nothing else fetches a page. Update radar is a version list, not a page watch.

**Card.** A delta bound to the boolean `changed` (it will render as `true` or `false`) and a list that stays blank for HTML (`competitor-watch.png` shows the sample, not a live fetch).

**Verdict.** Rethink as Page watch: the user names the URL, the consent sheet names that host, and the card is a timeline of checks. Drop the pricing-specific copy and the invented line items.

**Hard-coded.** The sample checklist and the mode sentence. No user files, which is correct.

**Overlaps.** Plugin health, if both are read as "is the desk ok". Policy and runtime are different selectors and should stay separate once both callbacks exist.

**Card.** Status, checklist, and a mode line in the sample (`compliance-posture.png`). Empty table-style sameness with the other status cards.

**Verdict.** Keep. The checklist must come from the host policy, and the empty state must say the policy state is not available rather than show the sample.

### Excel Report Watch (`excel-report`)

**Purpose versus behavior.** The description says it is the reference example, not a production report, and that it reports rows seen plus added and removed over 24 hours for `${workspace}/reports/*.xlsx`. That is what the legacy excel path does when no key column is declared: `rowsSeen`, `addedCount`, `removedCount`, the file name, and a window note. It writes snapshots under `${pluginData}`. The skill `workbook-report` tells the model to summarize that diff. The id and version stay `excel-report` `0.1.0` on purpose.

**Hard-coded.** The reports glob. No columns, so it cannot track a value. It reads the first matching workbook, not one the user picked. Sample file name `q4-pipeline.xlsx`, 428 rows, 12 added, 3 removed.

**Overlaps.** Sales 24h Delta declares the same glob and the same 24-hour diff. Revenue vs Target is the same reader with a column and a target.

**Card.** Four metrics in a row (`excel-report.png`). This is the most obvious "identical numbers" card. On the dashboard those four metrics would stack as four large figures, because that renderer only knows metrics.

**Verdict.** Rethink into the Workbook tracker: open the user's workbook, pick columns, show one figure, a sparkline, and a delta. Keep a minimal Class D fixture for authors outside the personal catalog. Stop describing the catalog entry as an example.

### Reconciliation Watch (`reconciliation-watch`)

**Purpose versus behavior.** Compare `${workspace}/finance/ledger*.xlsx` and `bank*.xlsx` on `Reference` / `Amount`. Compare builds keys from each side's `rows[].primary` (the key column). `value` is the size of the intersection. The UI label is "Unmatched". `delta` is left count minus right count, not an amount difference. The list includes left only, right only, and both. A blank side blanks the card and names the side. Amounts are not compared. Two rows with the same reference and different amounts show as "both".

**Hard-coded.** Both globs and both column pairs. Window `30d` with no date column, so it does not filter. Sample invoice ids and `value: 21` against five listed rows.

**Overlaps.** No other plugin compares two files. It is the compare pattern, and it should not be another sum.

**Card.** Metric, list, delta (`reconciliation-watch.png`).

**Verdict.** Keep. The user picks both files and the key column. The figure counts unmatched keys. Matched rows stay off the list unless the user asks to see them. Amount mismatches are a later column option, called out in the spec so "both" is not treated as reconciled when the amounts differ.

## Validator rules this audit held the plugins against

From `src/agentdesk/validator/lint.py` and `schema.py`. The spec's configuration model has to keep these.

- Class D. `permissions.shell` must be `"none"`. Render type must be `ui-schema`. `template` and `html` are rejected.
- Filesystem globs must be rooted at `${workspace}/` or `${pluginData}`. Absolute paths are rejected.
- A declared read glob must be referenced by a data source. A data source file must be covered by a declared read glob. Both failures are `over-permission`.
- `permissions.network.allow` must be empty. Network lives in `optionalPermissions` with a `userPrompt`.
- `http-get` cannot be combined with a filesystem read (`unsafe-network-filesystem`). Compare may not nest `http-get`.
- Element kinds are the ten named kinds. List rows cap at 8, table rows at 20, sparkline points at 12 to 30, when those arrays are inline in the ui-schema. A sparkline binding is not capped at render time beyond "nonempty numbers".
- v2 requires category, tags, icon, summary, description, exactly three highlights, and a sample. The sample must exist, parse, and stay under 32 KB. Unknown top-level keys are rejected.
- `llm` is declared `false` on every bundled plugin. The validator does not currently check that field.

The configuration model in the spec does not put user paths into the signed manifest. The host checks a grant at read time. That is how a picker can exist without an unscoped glob and without a new manifest per workbook.
