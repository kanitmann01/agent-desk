## 3. Offline catalog

frontend/src/marketplace/CatalogPage.tsx:

- Line 19 defines the cache key agentdesk.marketplace.catalog.v1.
- Lines 26-47 read and write { savedAt, data } in localStorage. Reads reject
  malformed JSON or a missing entries array. Writes swallow storage errors so
  a locked-down browser still gets the live catalog.
- Lines 78-85 save the cache only after an unfiltered catalog request
  succeeds. Filtered requests are never cached.
- Lines 86-96 on fetch failure read the cache only when no filter is active.
  With a cache, the page enters the ready state with an offline marker. With
  no cache, it enters the existing error state.
- Lines 202-212 keep the role="alert" error panel and add an honest reason:
  "No saved catalog for these filters is available offline." for filtered
  requests, or "No saved catalog is available offline yet." when nothing was
  ever saved.
- Lines 217-223 render the offline banner with role="status", "Offline",
  "Showing the last saved catalog, on <time>. Nothing was invented.", and a
  Retry button that re-runs the request.

The Installed page still fetches /api/marketplace/installed independently, so
installed plugins stay visible when the catalog fails but the installed
endpoint answers. No rows are synthesized.

Tests in frontend/src/test/marketplace-discover.test.tsx:

- Lines 108-124: fetch rejects, alert and no-cache text are shown, no plugin
  rows are invented, Try again succeeds.
- Lines 126-149: a first successful load caches the catalog; a later mount
  rejects then resolves on Retry; the status banner shows Offline and the
  saved catalog, then disappears after Retry.
- Lines 151-164: a filtered request does not use the unfiltered cache.

## 4. Walkthrough

scripts/marketplace_walkthrough.py is executable, server-free, and uses the
real marketplace modules over temporary directories. It prints numbered
steps and exits non-zero on failure. It makes no network calls.

Steps:

1. First run: GET /installed is empty.
2. Bundled catalog: 25 plugins.
3. Bundled packs: 3 packs.
4. Install the cfo pack: 8 plugins installed.
5. Installed records: 8 records, each pinned version matches the record and
   its sha256 matches the runtime digest.
6. Detail: GET /plugin/ar-aging returns plugin, installed record, and sample
   elements.
7. Install a custom org plugin walkthrough-recon 1.0.0. The custom catalog
   entry pins tree_digest(folder), because install now refuses an unpinned
   tree.
8. Update to 1.1.0 with an added filesystem.write scope: pendingConsent true
   and the added scope is reported.
9. Accept consent: 1.1.0 becomes active.
10. Update to 1.1.1 without the write scope: narrowing is accepted without
    consent, removed scope is reported.
11. Rollback restores 1.1.0.
12. Publish stages a pending publication (202, pendingId).
13. Admin approve publishes it and writes the org catalog.
14. Kill switch on source-ledger blocks a subsequent install with
    policy:kill-switch (403).
15. Audit export returns NDJSON with exactly at, action, pluginId, actor, and
    outcome, including install, pack-install, publish.approve, and
    policy.kill-switch events.

Latest run ended with:

    walkthrough: PASS

was empty because src/agentdesk/marketplace/catalog.py resolved the build
