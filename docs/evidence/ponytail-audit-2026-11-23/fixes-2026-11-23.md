## What changed

### 1. Decisions cell wraps (F1)

`frontend/src/index.css:642-645` now wraps the row, gives the text a 220px basis, and adds a `.decision-actions` container. `frontend/src/dashboard/Brief.tsx:512` wraps the action in that container, matching the server renderer at `src/agentdesk/server/pages.py:959`.

Measured at 1264x805 with sample data, before and after:

| decision text width | ~24.6px | 267px |
| actions width | n/a | 216px / 191px, wrapped below text |

| horizontal overflow | n/a | -10 (none) |

Screenshots: `f1-decisions-fixed-1264x805.png`, `inbox-actions-fixed-1264x805.png`.

### 2. Inbox action follows its context

`src/agentdesk/server/inbox_view.py:48-62` renders a recommendation's own `href` (when it starts with `/`) as an `<a class="btn btn-primary">`. Cards without a recommendation keep the accept button. Live DOM on `/inbox` with sample data:

```html
<a class="btn btn-primary" href="/assistant">Prep in Assistant</a>
<a class="btn btn-primary" href="/agents">Open Agents</a>
<button class="btn btn-primary" data-accept="sample-update">Accept update</button>
```

The first two no longer run `POST /accept`; the third still does.

### 3. Learned lines come from the store document

`src/agentdesk/recommend/rank.py:212-218` calls the module function `profile.learned_lines(document())` instead of a store attribute that never existed. Pinned by `tests/test_recommend_rank.py` and `tests/test_learned_profile.py`.

### 4. Ranking stops latching on an unusable reply

`src/agentdesk/recommend/rank.py:154-198`: ranks only visible waiting cards (`inbox.waiting()`), remembers an empty payload when no cards exist so a woken card is a change, and parses/validates the reply before auditing ok or remembering the input. An empty reply returns `skipped` with an audit `error` and no latch. Tests: `test_an_unusable_reply_does_not_latch_the_next_pass`, `test_a_snoozed_card_is_ranked_when_it_wakes`.

### 5. Stale sales delta is not shown as current

`frontend/src/dashboard/Brief.tsx:107-110` drops `status.delta` when `status.state === 'stale'`. The card already carries the stale marker. Test: `does not present a stale delta as today's move`.

### 6. Dismiss failure is visible, and the overflow count is a link

`frontend/src/dashboard/Brief.tsx:177-190` checks `res.ok` and catches transport errors, then renders a `role="alert"` line; the row stays. The overflow line is now `<a className="mono" href="/inbox">` (`Brief.tsx:208-210`). Tests: `keeps the row and says so when a dismiss fails`, `links the overflow line to the inbox`.

## Residual risk

- `Origin: null` is still allowed by `src/agentdesk/server/guard.py:88-91`. Tests `tests/test_server_guard.py:145-162` and `tests/test_server_auth.py:190-205` pin the allowance for the inbuilt webview (#60). Flipping it needs a CSRF token or an equivalent, which is out of scope here. Follow-up ticket to file.
- The Customize bento is still a second dashboard with its own card actions. #274/#275 cover moving those actions into the Brief and deleting the composition.
- The dismiss alert is cell-level, not row-level: with two failures in a row the same line reports the latest one. Acceptable at 3 visible rows; revisit if the cell grows.
- Network failure is simulated in the frontend test; it was not reproduced against a dead server in the browser.
